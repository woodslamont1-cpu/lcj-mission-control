Operator Safety & Audit Guidance

safe to act on trusted core optional / legacy fallback
  • Safe to act on today: review approve/request-changes/reject and enrollment approve/enroll.
  • Trusted core surfaces: systems overview, activity timeline, pending review queue, review history, enrollment queue, enrollment activity.
  • Optional legacy surfaces: status, config, metrics, recent events, recent tasks.
  • Use the trusted core first; treat legacy/fallback panels as context, not primary truth.

Demo Mode Focus

Keep the walkthrough tight: trust core → action → traceability → filter/export.
  • Show the trusted core panels first.
  • Use one review action and one enrollment action.
  • Open trace drill-down after each action.
  • Only expand legacy context if someone asks for raw status.

Recommended Demo Path

Trust core → action → traceability → filter/export
  1. Systems Overview
  2. Activity Timeline
  3. Pending Review Queue + one bounded review action
  4. Audit Drill-Down on a review item
  5. Enrollment Queue + one bounded enrollment action
  6. Audit Drill-Down on an enrollment item
  7. Filtered review history and enrollment activity
  8. Export previews
